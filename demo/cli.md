# Demo – CLI

User: `mds_test_2` (configured as Mercator → no `--pushing-entity-id` needed).

## 0. Setup (before the demo)

```bash
# from repo root
pixi shell          # makes `cm-de` available
source .env         # mds_test_2 credentials, ALLOW_HTTP, ENVIRONMENT=dta
unset PYTHON_LOG_DEBUG   # demo runs with INFO logs, not DEBUG

# clean + seed the bucket (delete targets must exist)
demo/helper_scripts/clean_native.sh
cd demo && ./helper_scripts/seed_delete_targets.sh

# yaml file paths are relative to the CWD
cd delivery_multiple_operations
```

## 1. Delivery (delete + upload)

The yaml deletes 4 files and uploads 16. 4 of the uploads re-use a deleted name (delete before upload).
This is a typical (although very reduced use case for producers where they first delete some dataset files and then upload some others)
Note the there is no need to specify the pushing-entity-id, this is all derived from the token, which is generated by the copernicus marine credentials.

Optional: validate without touching S3.

```bash
cm-de delivery --dry-run \
  --product-id GLOBAL_ANALYSISFORECAST_PHY_001_024 \
  --dataset-id cmems_mod_glo_phy-cur_anfc_0.083deg_PT6H-i_202406 \
  --file delivery_multiple_operations.yaml
```

```bash
cm-de delivery \
  --product-id GLOBAL_ANALYSISFORECAST_PHY_001_024 \
  --dataset-id cmems_mod_glo_phy-cur_anfc_0.083deg_PT6H-i_202406 \
  --file delivery_multiple_operations.yaml
```

Copy the `delivery_id` from the output (format `YYYYMMDDTHHMMSS-GLOBAL_ANALYSISFORECAST_PHY_001_024-NNNN`).


## 2. Status

```bash
export DELIVERY_ID=<delivery_id from above>

cm-de status --delivery-id $DELIVERY_ID              # summary
cm-de status --delivery-id $DELIVERY_ID --show-all   # every operation / file
```

## 3. List deliveries

```bash
cm-de list-deliveries --timeframe d     # last day
cm-de list-deliveries --timeframe all
```

## 4. Error: detected by the toolbox

2 of the files do not exist locally. The toolbox validates all files before uploading anything, so it stops with `InvalidFilesError` and no delivery is created.

```bash
cm-de delivery \
  --product-id GLOBAL_ANALYSISFORECAST_PHY_001_024 \
  --dataset-id cmems_mod_glo_phy-cur_anfc_0.083deg_PT6H-i_202406 \
  --file delivery_multiple_operations_user_error.yaml
```

## 5. Error: detected by OPDV

The yaml deletes a file that does not exist in the dataset. The toolbox cannot know that, so the delivery is submitted and OPDV rejects it afterwards.

```bash
cm-de delivery \
  --product-id GLOBAL_ANALYSISFORECAST_PHY_001_024 \
  --dataset-id cmems_mod_glo_phy-cur_anfc_0.083deg_PT6H-i_202406 \
  --file delivery_multiple_operations_opdv_error.yaml

export DELIVERY_ID=<delivery_id from above>
cm-de status --delivery-id $DELIVERY_ID --show-all
```

## 6. Error: delivery OK, error in publication

Toolbox and OPDV accept the delivery. The API is hardcoded to fail the publication of the file named `*_PUBERROR.nc`. Run it from its own folder (paths are relative to the CWD).

```bash
cd ../delivery_publication_error

cm-de delivery \
  --product-id GLOBAL_ANALYSISFORECAST_PHY_001_024 \
  --dataset-id cmems_mod_glo_phy-cur_anfc_0.083deg_PT6H-i_202406 \
  --file delivery_publication_error.yaml

export DELIVERY_ID=<delivery_id from above>
cm-de status --delivery-id $DELIVERY_ID --show-all
```
